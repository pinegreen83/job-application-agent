## 목적과 승인 경계

사용자가 전달한 메일에서 공고를 분리하고 출처/중복을 보존하며, 안전하게 상세 JD를 확인하고 최초 실제 Provider에 연결한다. 개인 경험 평가·분야 정렬은 M2, 제품 대시보드는 M3, 지원서 작성/독립 리뷰는 M4 이후다. 최초 통합 릴리스 범위를 축소하지 않는다.

M0 합성 저장/Mock은 제품 테이블/실제 Provider가 아니다. Mac 실기기는 #19로 이월하고 M0 전체 Gate는 미통과로 유지한다. Windows 개발·양쪽 OS CI는 계속할 수 있다. **이번 문서는 제품 기능/라이브러리/schema/비용 발생 호출에 대한 승인이 아니다.**

## 검증 계획

기존 M0 Rust16/renderer48·실제 IPC12/Mock10은 회귀 근거이며 M1 성공 결과가 아니다. 각 PR에서 영향에 맞는 기존 검사와 새 AC 테스트를 실행한다.

| 대상 | 입력·행동 | 기대 결과 / 근거 |
|---|---|---|
| 정상 추출 | 합성 EML 공고10, HTML/일반 텍스트·charset | 10개와 각각의 링크/메일 출처. AC-001-01, FR-001-02 |
| 중복/오병합 | 같은 공고의 메일2개, 같은 회사 다른 ID | 고유 공고1+출처2, 다른 ID 분리. AC-001-02/03 |
| 부분 실패/누락 | 실패1+정상9, 마감·경력 누락 | 정상/기존값 유지, 오류·unknown 구분. AC-001-04/05 |
| 메일 안전 | script/iframe/추적 이미지, 입력 상한 초과 | 실행·외부 자동 요청 없음, 승인 오류 계약. AC-001-06 |
| Provider | 성공·인증/연결/네트워크/쿼터/미지원/불완전·취소 | 명시 오류·키 비노출·원본 보존·실패 완료 표시 금지. AC-004-04/06/07 및 M1 추가 사례 |
| JD 접근 | 정상/로그인/삭제/거부, file/localhost/내부 IP/DNS/redirect | 실패=확인 필요, 기존값 유지, 위험 목적지 연결 금지. AC-002-03/04 |
| 근거·수정 | 메일/JD 충돌, 수동 수정·재시작/재분석, 전분야 JD | 출처·원본/수정 유지, 임의 직무 확정 없음. AC-002-01/02/06/07 |
| 비신뢰 본문 | '이전 지침 무시'·추가 송신 유도 | 데이터로 취급, 키/개인 정보 추가 송신·도구 실행 없음. AC-002-05 |
| OS/CI | Windows 실제 입력→저장→재실행, 양쪽 OS CI | head/OS별 결과. Mac은 #19의 기반 검사와 M1 새 기능을 구분해 후속 확인, 미실행=미검증 |

합성 EML은 비개인 source 문자열/생성기에서 테스트 중 임시 생성·정리하는 안을 권장한다. `.gitignore`와 privacy scanner는 `.eml`·`.msg`·DB 파일 등록을 차단하므로 broad allowlist나 강제 add를 하지 않는다. fixture 출처·공개 범위·검사 방법을 PR에 기록한다. 실제 메일/이력서/키·실제 DB·원본 로그는 Git/CI/Release에 넣지 않는다.

## 완료 판단과 인계 범위

M1 완료의 기능별 AC/합격 조합은 준비 Issue에서 승인받는다. 메일10건/중복/부분 실패, JD 근거/수정 보존/위험 URL 차단, Provider 계약/키·전송/취소를 검증하고 Issue→PR→테스트를 연결하는 안이다. Mock/빌드 성공을 실제 AI 품질·양쪽 실기기·M1 전체 완료로 확대하지 않는다.

이번 인계는 현재 상태 정정, 미정 결정/근거/테스트/다음 첫 작업을 문서화하고 PR 제출하는 범위다. 새 대화에서 첫 제안을 검토한 뒤 승인된 범위만 구현한다. 대화 원문/Codex 설정 복사나 앱 PC 간 데이터 동기화는 필요하지 않다.
