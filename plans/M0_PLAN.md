## 승인 범위

이번 승인은 Public 저장소 생성, 기존 명세 초기 등록, 준비 Issue와 이 계획·템플릿의 문서 PR 작성이다. M0 구현, 상세 Spec 전체 또는 AC-M0-01~06의 최종 승인으로 간주하지 않는다. 사용자 리뷰 결과를 Issue/PR에 기록한 뒤 승인된 작업별 Issue와 브랜치를 만든다. Codex는 merge하지 않는다.

현재 준비에는 생산 코드, 의존성 설치, 실제 LLM 호출, 앱 빌드·설치본·태그·Release가 없다. 최초 릴리스는 M1~M7을 연결한 통합 프로토타입이며 M0 완료와 구분한다.

## 요구사항과 단계별 작은 PR

UR-001~016은 최종 사용자 흐름의 배경이다. M0에서 메일 수집·JD 해석·실제 개인 자료·지원서·알림 기능을 구현하지 않는다. 직접 적용하는 요구는 NFR-001/003/004/006/011 및 DEV-001~008이며 아래 매핑은 M0 기반 부분만 뜻한다.

각 행은 후속 Issue/PR 제안이다. 지금 생성한 Issue는 준비용 #1뿐이다. 예상 파일명·라이브러리·명령은 계획이며 실제 구조는 해당 설계 승인 후 확정한다. 각 PR은 해당 범위의 테스트 케이스를 먼저 기록한다.

## 이번 준비의 Done과 검증 경계

- 공개 대상은 기존 프로젝트 명세와 준비 문서/템플릿/제외 규칙뿐이다. 실제 메일·이력서·PDF·키는 없다.
- 문서 로컬 링크/FR·AC 참조, 표 구조, 변경 whitespace와 파일 목록을 확인해 PR에 결과를 남긴다. 패턴 검사 통과는 모든 종류의 비밀값 부재를 보증하지 않으므로 공개 파일 내용을 함께 검토한다.
- main 최초 등록은 기존 문서와 `.gitignore`에 한정한다. #1 브랜치의 PR은 사용자가 검토하고 merge한다.
- `.gitignore`는 추가 방지 장치다. 다른 경로/확장자의 개인정보도 commit 전에 검토해야 하며, 합성 fixture 예외는 출처·비식별 검토와 PR 승인을 거쳐 좁게 추가한다.
- Issue/PR 템플릿은 체크리스트다. 현재 CI·브랜치 보호·기밀 스캐너가 설치되었다는 뜻은 아니다.

| 대상 | 이번 상태 | 남은 증거/리스크 |
|---|---|---|
| Windows 문서/Git 준비 | PowerShell로 구조·링크·민감 패턴·Git 상태 점검 (세부 결과는 PR) | 앱 실행/빌드/설치 미검증 |
| macOS | 미검증 | 환경/CPU 대상 확정, CI 빌드와 실기기 스모크 필요 |
| AC-M0-01~06 | 모두 미실행, Gate 미통과 | 앱 코드·의존성·CI가 아직 없음 |
| Provider | Mock/실제 연결 모두 미구현 | Mock 통과와 실제 AI 품질/연결 검증은 별개 |
| 공개 배포 | 소스 문서 저장소만 생성 | 라이선스·OS 대상·서명·러너 조건·릴리스 승인 필요 |

## 사용자 리뷰 후 다음 단계

1. AC-M0-01~06과 이 계획의 테스트/Done 경계를 승인하거나 수정한다.
2. M0-A의 Spec 범위·테스트를 확정하고 별도 Issue/브랜치에서 시작한다. B~F도 각 작업 전 필요한 설계 결정을 확인한다.
3. OS 조합/실기기 확보와 CI 조건을 확인한다. 후속 OQ는 해당 기능 전에 해결한다.
4. 각 PR은 Rust 판단·검사 결과·Windows/macOS 미검증과 민감정보 검토를 기록하고 사용자 merge를 기다린다.
