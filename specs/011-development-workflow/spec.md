# SPEC-011 — SDD · GitHub Issue/Branch/PR 리뷰 개발 프로세스

- 상태: Draft / 전 마일스톤 / P0
- URS: DEV-001~DEV-008

## 운영 요구사항
- **FR-011-01** 구현 전 상위 URS와 관련 Spec의 ID/수용 기준을 확인한다. 미확정 요구사항이면 먼저 검증·승인을 요청한다.
- **FR-011-02** 모든 구현/설계 작업은 GitHub Issue에 기록하고 기능별 브랜치에서 진행한다. `main` 직접 구현 금지.
- **FR-011-03** 기능 완료 시 관련 Issue/Spec, 코드 변경 이유, 설계·Rust 학습 포인트, 테스트 명령·결과를 포함한 PR을 연다.
- **FR-011-04** 사용자가 PR을 직접 검토한다. 수정 요청을 반영하고 사용자 Merge 결정 전 임의 병합하지 않는다.
- **FR-011-05** CI 테스트 및 OS별 빌드 결과를 PR에 첨부한다. 실패/미검증을 숨기지 않는다.
- **FR-011-06** 지정된 마일스톤에서 승인된 코드로 Windows/macOS 설치 파일을 생성해 다운로드할 수 있게 한다.
- **FR-011-07** URS↔Spec↔Issue↔PR↔테스트 결과↔릴리스 버전의 연결을 문서/링크로 유지한다.

## 수용 기준
- **AC-011-01** Given 신규 기능 작업, When 구현 시작 전 기록을 확인하면 Then 관련 Issue와 Spec/AC가 존재한다.
- **AC-011-02** Given 기능 개발 중, When Git 브랜치를 확인하면 Then `main`이 아닌 이슈 연결 브랜치에서 작업 중이다.
- **AC-011-03** Given PR, When 사용자가 검토하면 Then 명세 대비 변경 사항과 테스트 결과 및 미검증 항목이 명시되어 있다.
- **AC-011-04** Given 사용자 리뷰 전, When CI가 통과해도 Then 자동 Merge되지 않는다.
- **AC-011-05** Given 지정된 마일스톤 태그, When Release가 완료되면 Then Windows/macOS 다운로드 자료와 릴리스 노트가 존재한다.

## 비고
1인 프로젝트는 자신이 작성한 PR의 필수 GitHub 자기 승인 규칙과 사용자 수동 리뷰 기록을 혼동하지 않는다. Branch Protection/Ruleset 적용 가능 여부는 저장소 플랜 및 권한을 확인한 뒤 확정한다.
