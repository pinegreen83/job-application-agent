# SPEC-001 — 메일 입력, 다중 공고 분리 및 중복 통합

- 상태: Draft / M1 / P0
- URS: UR-001, UR-002, UR-003; NFR-001, NFR-010, NFR-011

## 기능 요구사항
- **FR-001-01** 사용자가 선택한 메일을 파일로 첨부해 로컬 앱에 입력한다. 최초 지원 형식은 `.eml` 제안이며 본문 붙여넣기·다중 파일을 포함한 세부 범위는 URS OQ-01에서 확정한다.
- **FR-001-02** MIME/HTML/일반 텍스트를 파싱하여 메일 한 통의 모든 채용공고 카드/링크를 개별 후보로 추출한다. 메일의 인코딩(EUC-KR 등)을 처리한다.
- **FR-001-03** 공고별 회사, 제목, URL, 경력, 지역, 고용 형태, 마감 표현을 추출하고 원본 출처를 기록한다.
- **FR-001-04** 고유 채용공고 ID 또는 정규화 링크 등 출처를 활용해 기존 공고에 연결한다. 같은 회사의 다른 공고는 병합하지 않는다. 판단 불명 시 '중복 가능'으로 둔다.
- **FR-001-05** 일부 카드의 파싱 오류가 전체 메일 분석을 중단시키지 않는다.
- **FR-001-06** HTML 메일의 script/iframe/외부 추적 리소스가 자동 실행 또는 요청되지 않는다. 원본은 비공개 로컬에 보관하며 공개 자료·오류 메시지·로그에 개인정보가 노출되지 않는다.

## 수용 기준
- **AC-001-01** Given 공고 10건이 든 합성 EML, When 입력하면 Then 10개 개별 공고 후보와 각각의 원문 링크/메일 출처가 확인된다.
- **AC-001-02** Given 같은 공고가 든 두 메일, When 모두 입력하면 Then 고유 공고는 하나이고 `JobOccurrence`에 두 메일 연결이 보존된다.
- **AC-001-03** Given 같은 회사의 서로 다른 채용 ID 공고, When 입력하면 Then 별도 공고로 기록된다.
- **AC-001-04** Given 마감일·경력 등이 누락된 카드, When 파싱하면 Then 미확인 상태이지 임의 값이 아니다.
- **AC-001-05** Given 파싱 실패 카드 1개와 정상 카드 9개, When 처리하면 Then 정상 9개가 유지되고 실패 원인을 확인할 수 있다.
- **AC-001-06** Given HTML 추적 이미지와 iframe, When 가져와 미리보기 하면 Then 외부 자동 로딩·스크립트 실행이 일어나지 않는다.

## 비범위/검증 데이터
임의 수신함 스캔, 자동 메일 계정 연동, 메일 첨부파일 자동 실행은 범위 밖. 샘플 EML은 **개인정보와 추적 URL을 제거한 합성 파일**을 사용한다.
