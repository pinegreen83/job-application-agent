# SPEC-002 — 상세 JD 확인 및 구조화

- 상태: Draft / M1 / P0
- URS: UR-004; NFR-002, NFR-010

## 기능 요구사항
- **FR-002-01** 공고 원문 URL을 안전하게 확인하고 상세 JD의 담당 업무, 필수/우대 요건, 경력 조건, 마감일, 지원 링크를 추출한다.
- **FR-002-02** 메일 카드의 정보와 상세 JD의 출처를 각각 보존하며 충돌·변경 이력을 표시한다.
- **FR-002-03** 공고가 동적 페이지/로그인 필요/삭제/접근 거부로 확인 불가하면 추정하지 않고 `확인 필요`로 처리한다.
- **FR-002-04** URL/HTML을 신뢰하지 않는 데이터로 취급한다. 내부망/로컬 접근, 실행 코드, 위험한 리다이렉트 등을 차단한다.
- **FR-002-05** 사용자는 분석 결과를 원문과 비교하고 필요한 항목을 수동 수정할 수 있다. 원본 추출값과 수정값은 구별한다.
- **FR-002-06** 전분야 공고처럼 단일 직무를 확정할 수 없으면 역할이 불명확하다고 표시한다.

## 수용 기준
- **AC-002-01** Given 접근 가능한 상세 JD, When 분석하면 Then 각 요구사항과 해당 원문 근거가 함께 표시된다.
- **AC-002-02** Given 메일엔 '채용시'라고 적히고 JD에는 다른 표현이 있는 공고, When 분석하면 Then 출처 충돌이 확인 가능하다.
- **AC-002-03** Given 로그인 벽/접근 실패, When 수집하면 Then 오류와 확인 필요 상태를 기록하고 기존 공고는 보존한다.
- **AC-002-04** Given `file://`, localhost 또는 내부 네트워크로 이동하는 URL, When 조회하면 Then 연결이 차단된다.
- **AC-002-05** Given 상세 JD에 '이전 지침 무시' 문장이 있을 때, When 분석하면 Then 지시로 실행하지 않고 원문 데이터로만 취급한다.
- **AC-002-06** Given JD 분석값을 사용자가 수정, When 저장 후 앱을 재시작하면 Then 원본 추출값과 수정값이 구별되어 유지되고 현재 표시값의 출처를 확인할 수 있다.
- **AC-002-07** Given 단일 직무를 특정할 수 없는 전분야 공고, When 분석하면 Then 직무 불명확 상태를 표시하고 임의 직무로 확정하지 않는다.

## 비범위
모든 채용 플랫폼 접근 성공 보장, 자동 로그인, 지원사이트 제출, 법적 의미의 지원자격 보장.
