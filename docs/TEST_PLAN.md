# 검증 및 수용 테스트 계획 — v0.2

각 `specs/**/spec.md`의 AC가 테스트 기준이다. 실제 구현 전에는 **테스트 케이스 정의**와 사용자 승인부터 수행한다.

## 테스트 계층
- **Unit (Rust):** EML/MIME/인코딩 파싱, 다중 공고 추출, canonical URL/중복 판정, 자격요건 표현, 문서 인덱싱/검색, 상태 전이, 승인 버전 확인, 알림 대상 집계.
- **Unit (TypeScript):** 공고 목록 정렬, 화면 상태, 리뷰 Diff 표시, 문항별 복사 형식, 오류·불명 상태 표시.
- **Integration:** Tauri commands/권한, Rust 서비스↔SQLite/로컬 파일, Provider Mock, JD Fetch Mock, 창 재시작 후 데이터 복원.
- **E2E:** 합성 채용 메일→공고 등록·우선순위→간편/자체 작성→AI 리뷰→사용자 검토→자료 내보내기→사용자가 직접 제출 완료 표시→PDF 연결→알림 확인.
- **Security:** 실제 API 키·문서·메일의 Git/Actions/릴리스 누출 없음. 메일 HTML 실행 차단, 원격 이미지 자동 요청 차단, 의심 URL/리다이렉트/내부망 차단, prompt injection과 문서 사용 금지 사실 검증.
- **Platform:** Windows/macOS WebView UI, 로컬 DB/파일 경로, 대화상자, 시스템 알림, 설치 파일 실행, 업데이트 알림.
- **AI 평가:** Retrieval 관련성(출처별), 필수조건 판정 누락, 허위 경험/경력 도입, 독립 리뷰가 잡아낸 오류, 이용자의 최종 수정량. 모델 출력의 비결정성을 인정하고 자동 테스트에 고정 Mock 사용.

## 자동 동작 검사와 실제 AI 품질 평가
- **고정 Mock 검사:** 프로그램의 호출·오류·저장·출처 연결·정렬·승인 무효화를 검증한다. Mock 통과를 실제 모델의 JD 해석·추천 품질 검증으로 보고하지 않는다.
- **AI 품질 평가:** 합성 JD·프로필·선택 분야별 기대 판단과 근거를 정하고 실제 출력의 분야 연관성, 자격 unknown/unmet 구분, 경험 검색, 허위 주장·독립 리뷰 결과를 평가한다. 정답 표본·허용 오차·합격 기준은 OQ-08로 확정한다.
- **단계 승인:** 각 기능 착수 전에 FR→AC→테스트 케이스를 연결한다. 모든 후속 OQ를 미리 해결할 필요는 없지만 현재 작업의 기대 결과가 미정이면 구현 전에 확정한다.

## 가상 데이터 세트
1. 10개 공고가 포함된 합성 EML(실제 예시 메일의 **구조만 참조**, 수신자·메시지 ID·추적 URL·회사 정보를 그대로 공개하지 않음).
2. 중복 공고를 포함한 두 번째 메일, 같은 회사의 다른 공고, 원문 접근 실패 공고.
3. 신규/경력 3년 이상/분야 불일치/마감 누락/전분야 공고.
4. `verified/uncertain/forbidden` 경험이 혼합된 가상 마스터 이력서.
5. 간편 지원+자체 문항 지원 시나리오, 허위 수치가 포함된 생성 결과 Mock.
6. 화면 캡처의 작은 글씨/중복 문항/형식 오류/개인정보 포함 케이스.
7. 승인 뒤 초안 수정, 사용자가 제출하지 않았는데 완료로 표시되는 오류 방지.
8. 앱 종료 중 지나간 아침 알림, 앱 재실행 시 미확인 항목 표시.
9. 선택 분야와 연관성이 높은 A/낮은 B의 고정 평가 결과로 기본 순서와 근거 검사(AC-007-04). 분야와 개인 경험 근거가 어긋나는 사례도 구분한다.
10. 분석값 수동 수정 후 재시작, 첨부 교체 후 재승인, 취소/쿼터/불완전 응답 후 기존 저장본 보존, 문항 글자수·금지 정보·질문 불일치 경고.

동점·분야 미선택·분석 실패·필수 자격 미충족의 정렬 기대값과 문항 글자수 계산 방식은 해당 Spec 착수 전에 추가한다. 별도 개인 선호 입력·평가는 최초 릴리스 테스트 대상에서 제외한다.

## 최초 통합 프로토타입 수용 흐름
Windows/macOS 각각에서 메일 첨부 → JD 분석·분야 중심 정렬 → 사용자 지원 결정 → 간편/자체 양식 작성 → 독립 AI 리뷰(간편 지원) → 사용자 승인 → 직접 제출 자료 제공 → 사용자 완료 기록·실제 제출본 PDF 연결 → 전형 갱신·아침 알림을 검증한다. 업데이트 안내·사용자 선택 설치도 검사한다. 실제 사이트 제출을 자동 실행하지 않으며, 일부 단계만 통과한 중간 설치본을 최초 통합 릴리스 완료로 보고하지 않는다.

## 성능 비교 원칙
Tauri 선택으로 인한 앱 크기·메모리·시작 시간은 동일 빌드 조건/OS/입력 데이터로 실측할 때만 기록한다. Electron 대비 우수하다는 무근거 수치는 작성하지 않는다.
