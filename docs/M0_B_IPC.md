# M0-B 최소 IPC·권한 계약

관련: [Issue #10](https://github.com/pinegreen83/job-application-agent/issues/10), AC-M0-02, NFR-011, DEV-002~006/008, [M0 계획](../plans/M0_PLAN.md).

2026-11-19 사용자가 Issue #10의 계약·테스트 제안을 `제안대로 승인`했다. M0-C의 DB schema, M0-D의 Provider 계약, 후속 제품 Spec 전체 승인은 아니다.

## 호출 계약

렌더러는 `m0_validate_record`에 `{ record: { id, text } }`를 전달한다.

- `id`: `synthetic-m0-001`만 허용.
- `text`: 1~256 Unicode scalar 값. 공백만 있는 값과 제어 문자는 거부. 잘라내기·정규화하지 않는다. UTF-16 길이나 사용자에게 보이는 글자 묶음 수와는 다를 수 있다.
- 최상위와 record 모두 필수 필드 누락·타입 불일치·추가 필드를 거부한다. JSON 객체 이외의 전송 본문도 거부한다.
- 성공: `{ id, text, status: "validated" }`. 검증은 저장·분석 성공을 뜻하지 않는다.
- 실패: `{ code: "INVALID_RECORD", message: "합성 레코드의 형식과 입력 범위를 확인해 주세요." }`. 원문·내부 오류를 반환하거나 기록하지 않는다.

`Request`의 본문을 빌려 엄격한 구조로 역직렬화하고, 소유한 문자열은 검증 뒤 응답으로 이동한다. 역직렬화 오류를 고정 오류로 바꾸므로 잘못된 타입/추가 필드에 담긴 원문도 응답에 반사하지 않는다. DB·환경 변수·파일·네트워크·장기 async 작업은 없다.

## 권한과 화면

`build.rs`의 AppManifest와 `permissions/autogenerated/m0_validate_record.toml`이 앱 명령을 ACL에 연결한다. `main-synthetic-validation` capability를 설정에서 명시적으로 선택하고 local `main` 창에 `allow-m0-validate-record` 하나만 부여한다. remote URL·다른 창·core:default·파일/셸/HTTP plugin은 허용하지 않는다.

CSP `connect-src`에는 Tauri 로컬 IPC 전송(`ipc:`, `http://ipc.localhost`)만 추가했다. 개발 서버는 기존 `127.0.0.1:1420`을 유지한다. `ipc.localhost`는 Tauri 전송용 이름이며 외부 API endpoint가 아니다.

화면의 합성 입력 검증은 typed wrapper를 사용한다. 브라우저에서는 버튼을 비활성화하고 native 실행이 필요하다고 표시한다. native 실패·프레임워크 오류·잘못된 성공 응답은 고정된 오류로 표시하며 원본 예외를 로그/화면에 출력하지 않는다. 호출은 5초 뒤 UI에서 실패로 처리하며, 이 제한은 네이티브 작업 취소 계약이 아니다(현재 명령은 동기 검증뿐).

## 자동 검증과 근거의 한계

| 계층 | 검사 | 증명 범위 |
|---|---|---|
| Rust unit | Unicode/256자 경계, 빈 값·공백·제어 문자·초과 길이·ID, 필수/타입/추가 필드, 합성 비밀 원문 비반사 | 입력·오류 계약 |
| Tauri MockRuntime 통합 | 실제 handler·생성 ACL, 정상·잘못된 본문, 다른 창/remote 거부, 등록된 core 명령과 미등록 명령 거부 | Rust handler·ACL. 실제 WebView/CSP 증거는 아님 |
| Playwright | 브라우저 native 불가, 성공·입력 오류·transport 실패·잘못된 응답 시뮬레이션, 입력 수정 시 이전 성공 무효화, desktop/narrow | 렌더러. native IPC 성공 증거는 아님 |
| OS CI | 기존 setup/build, Rust fmt/check/clippy/test, Tauri debug 비번들 build, lockfile 무변경 | 각 runner의 검사·컴파일 |

Windows MockRuntime 테스트도 네이티브 메뉴의 `TaskDialogIndirect`에 링크된다. MSVC에서는 링커가 Common Controls v6 manifest를 앱과 테스트 실행 파일에 동일하게 포함하도록 했다. Tauri 기본 manifest와의 중복 포함은 피한다. 이는 권한 상승이나 보안 정책 변경이 아니다.

앱과 MockRuntime은 같은 handler·context 함수를 사용한다. `generate_context!`는 한 곳에서만 확장해 macOS의 프로세스 단위 Info.plist 심볼 중복을 피하고 같은 설정·ACL을 검증한다.

## Windows·Mac 실기기 스모크

각 OS에서 아래를 따로 기록한다. Windows 성공이나 CI 성공으로 Mac 실기기 확인을 대체하지 않는다.

1. 현재 PR 브랜치를 checkout하고 commit을 기록한다. `npm run setup -- --tests`, `npm run doctor -- --native`를 실행한다.
2. `npm run tauri dev`에서 합성 입력에 `합성 IPC 🦀`를 입력하고 **Rust로 검증**을 누른다. `입력 검증 완료 · 저장·분석되지 않았습니다.`를 확인한다.
3. 입력을 비우고 다시 실행해 `INVALID_RECORD` 오류 표시를 확인한다. 다시 정상 텍스트를 검증한다.
4. **개발용 IPC 경계 검사**를 펼쳐 **경계 검사 실행**을 누른다. 고정 합성 입력의 정상·잘못된 타입/범위/필드/ID, 미허용 core/파일/셸/미등록 명령까지 **12/12 통과**인지 확인한다. 실패 항목이 있으면 통과로 보고하지 않는다.
5. 창을 닫고 명령을 다시 실행해 같은 화면·검증이 동작하는지 확인한다. commit/OS·CPU/도구 버전·정상/오류/경계/종료·재실행 결과를 기록한다.
6. production CSP도 확인하려면 `npm run tauri build -- --debug --no-bundle --ci -- --locked` 후 `backend/target/debug/`의 실행 파일을 열어 같은 검증을 한다. 설치 파일·Release를 게시하지 않는다.

진행 결과와 각 OS 미검증 사항은 연결된 PR에서 관리한다. M0-B 수용과 M0 전체 Gate 통과는 별개다.
