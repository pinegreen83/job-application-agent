# 마일스톤 및 Release Gate — v0.2

**상태:** 최초 통합 프로토타입 범위 확정. 내부 단계·세부 AC·Issue는 관련 작업 착수 전에 검토한다.

## SDD 절차
`사용자 요구사항 검증(URS) → 기능별 승인 Spec → Issue → 기능 브랜치 → 구현/AC 테스트 → PR → 사용자 리뷰/수정 → Merge → 마일스톤 태그/OS별 Release`

구현은 `main` 직접 수정 없이 작은 단위로 진행한다. M0~M7은 하나의 최초 통합 프로토타입을 만드는 내부 단계다. 공고 분석만으로 최초 릴리스를 완료하지 않으며 자동 제출은 기능 범위에 **없음**.

### 의존 관계
Provider 연결·보호 저장·오류 처리는 M4 전용 기능이 아니다. M0에서 Mock 호출 계약을 검증하고 M1에서 최초 실제 Provider를 연결해 JD 분석, M2 평가, M4/M5 생성·검토가 재사용한다. 첫 공급자/모델은 M1 착수 전에 정한다. Mock 테스트와 실제 연동 검증을 구분하고 비용 발생 호출은 사전 승인 범위에서만 수행한다.

### M0 수용 기준 초안 — 계획 승인 시 확정
후속 기능의 미정 사항을 모두 해결하는 대신 M0 범위의 다음 기준을 먼저 확정한다.

| ID | 관련 요구사항 | 테스트와 완료 기준 |
|---|---|---|
| AC-M0-01 | FR-006-01, AC-006-01 | 문서화한 설치·개발 실행 절차로 합성 데이터 기본 화면이 열리며 외부 키가 필요 없다. |
| AC-M0-02 | ARCHITECTURE 책임/경계, NFR-011 | 허용된 테스트용 Rust 명령은 호출되고 잘못된 입력·미허용 명령은 거부된다. UI에 임의 파일/셸 접근과 비밀값을 노출하지 않는다. |
| AC-M0-03 | NFR-001 | 합성 레코드를 앱 전용 로컬 SQLite에 기록한 뒤 재실행하면 복원된다. 저장 실패는 오류로 표시한다. |
| AC-M0-04 | FR-004-01/02/07 | Mock Provider의 정상·실패 응답을 공통 계약으로 처리하며 실제 API 호출이나 키 없이 테스트한다. |
| AC-M0-05 | FR-006-02/06, AC-006-02/04 | PR 검사에 Rust/TS 정적 검사·단위/통합 테스트·기밀 스캔·양쪽 OS 빌드가 있고 각 결과가 기록된다. |
| AC-M0-06 | NFR-004, AC-006-06 | Windows/macOS 기본 창·IPC·로컬 저장 스모크 결과를 각각 기록한다. 미실행 OS는 미검증으로 남기고 M0 Gate 통과로 선언하지 않는다. |

최초 통합 릴리스 Gate는 M1~M6의 전체 사용자 흐름, M7의 설치·업데이트 안내 및 양쪽 OS 검증을 함께 충족하는 것이다. 기능별 Draft는 착수 전에 승인하고, 중간 설치본에는 미완성 범위를 명시한다.

## 빌드·배포 규칙
- 모든 PR: lint, Rust/TS 타입·정적 검사, 단위/통합 테스트, 가능한 OS 빌드 및 비밀키 검사.
- 병합: 사용자 PR 리뷰 뒤 `main`에 통합. CI 상태를 기록한다.
- **지정한 마일스톤**: 설치 가능한 Windows/macOS 빌드를 GitHub Actions가 만들고 GitHub Releases에 아티팩트를 게시한다. 모든 중간 커밋마다 릴리스하지 않는다.
- macOS Apple Silicon/Intel 및 Windows 아키텍처, 코드 서명/공증은 대상 조합을 먼저 확인한다. 빌드 성공만으로 실기기 정상 동작을 주장하지 않는다.
- 자동 업데이트 설치 대신 최신 버전 **알림**을 제공하고 사용자에게 선택권을 둔다.
